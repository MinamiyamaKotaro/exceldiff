# `.xlsx` 差分検出ツール 要求仕様書

*[English](requirements.en.md)*

## 0. 実装言語

Rust

## 1. プロジェクト概要

`.xlsx` ファイルは日本のビジネスシステムでよくgit管理・PRレビューの対象になるが、`git diff` はそこから何も意味のある情報を返さない——`.xlsx` はZIP圧縮されたXMLパーツの集合であり、セル1つを変えただけでも共有文字列テーブルの並びやZIP圧縮結果全体が変わり得るため、gitからはただのバイナリ差分にしか見えない。

本プロジェクトはこのギャップを埋める: 変更前後の `.xlsx` をそれぞれパースして2つの `Workbook` として復元し、セル単位の追加・変更・削除を比較する差分エンジンを核に、その結果をMarkdownテキストやExcelライクなグリッドのHTMLビューとしてPRコメントへ要約するライブラリ・CLI・GitHub Actionを一貫して提供する。対象は日本の業務システムでよく見られる、行・列数が極端に多い(「方眼紙Excel」)シートや結合セルを多用したファイル。

## 2. 基盤パーサーとの関係

本プロジェクトのOOXMLパース部分(ZIP展開・サニタイズ・ストリームパース・共有文字列/スタイル解決・結合セル解決)は、姉妹プロジェクトである[`xlsxparser`](https://github.com/MinamiyamaKotaro/xlsxparser)と同じ設計・実装をベースにしている。パース処理自体の詳細な要求仕様(5フェーズ・パイプライン、疎行列によるメモリ最適化、結合セルの透過アクセス等)は`xlsxparser`側の要求仕様書を参照——本書はその上に成り立つ、本プロジェクト固有の要件(差分検出・出力・配布)のみを定義する。

パース処理自体の低メモリ・高速さは、本プロジェクトにとって単にパーサーの軽さにとどまらない——**差分計算そのものの速度と正確さに直結する**。大量セルを持つシートの2バージョンを突き合わせる差分エンジンの計算量・メモリ使用量は、パーサーが返すデータ構造の疎密に大きく依存するためである。

## 3. 差分エンジンの要件

### 3.1 セル単位の差分検出

- 変更前後2つの `Workbook` を比較し、シートごとにセルの追加(Added)・変更(Modified)・削除(Deleted)を検出する。
- 単純な座標一致比較(同じ `(row, col)` 同士を比較)を基本方式とする。

### 3.2 行/列アライメント検出(誤検出対策)

- 座標一致比較だけでは、シート中間への1行/1列の挿入だけで、それ以降の全セルが座標的にずれてModifiedと誤検出されてしまう。
- 行アライメント検出・列アライメント検出により、内容の一致度から「挿入/削除された行・列」を検出し、実際には変化していないセルをModifiedとして報告しない。
- 座標一致/行アライメント/列アライメントのうち最も変更が少なく報告される方式を自動選択する「ベストエフォート」モードを既定とし、アライメント検出をスキップした単純な座標比較への切り替えも可能とする。

### 3.3 対応する変更種別

セル値だけでなく、以下の要素も差分検出の対象に含める:

- セルのスタイル(フォント・配置・書式・塗りつぶし色・罫線)
- 結合セルの範囲・状態
- 埋め込み画像(アンカー位置・ハイパーリンク)
- セルのハイパーリンク
- 列幅・行高
- シートの可視性(表示/非表示/完全非表示)

## 4. 出力形式の要件

### 4.1 Markdownテキスト差分(GitHub PRコメント向け)

- GitHub Flavored Markdownとして、PRコメントに直接貼り付けられる形式で出力する。
- GitHubのコメントサニタイザを通っても内容が失われないよう、装飾的なHTML/CSSを一切含まない。
- 1シートあたりに表示するセル変更ハンク数の上限を設定可能とする——巨大な変更を全展開してコメント自体が肥大化するのを防ぐ。

### 4.2 Excelライクなグリッドビュー(HTML)

- 変更のあったシートについて、Before/Afterを左右に並べたExcelライクなグリッドをHTMLとして生成する。
- スクリーンショット画像ではなく実際のHTMLとして出力し、大きなシートでも縮小されて内容が潰れず、ブラウザでスクロール・拡大しながら閲覧できるようにする。

## 5. 配布・パッケージングの要件

### 5.1 CLI

- 1つの変更ファイルの差分を、gitのステータス(追加/変更/削除)と変更前後の実ファイルパスから、Markdown文字列として標準出力へ書き出す。
- 1ファイルのパースエラーが他のファイルの差分表示を止めない——エラー自体も差分結果の一部として出力する。

### 5.2 GitHub Action

- PRで変更された `.xlsx` ファイルごとに、上記CLIの出力をまとめて1つのPRコメントとして自動投稿(または既存コメントの更新)する。
- 呼び出し元が、対象とする `.xlsx` ファイルパターン・コメント投稿有無・1シートあたりの表示上限・差分方式(座標比較/ベストエフォート自動選択)などをカスタマイズできる。
- 呼び出しのたびにソースからビルドする方式に加え、事前ビルド済みバイナリのダウンロードによる高速化の余地を残す。
- PRの累積差分(既定)に加え、PRを構成する各コミット単位での差分表示への切り替えを可能とする。

## 6. セキュリティ要件

- 信頼できない `.xlsx` ファイルを扱う前提とし、パース時のZip Bomb・Zip Slip・XXE対策はパーサー側の要件を継承する。
- 差分結果として出力するセルの文字列値(数式の計算結果を含む)はいかなる段階でもエスケープせずそのまま通過させる——これはJSON/Markdown出力としては安全だが、差分結果をCSVや他のスプレッドシート形式へ再出力する呼び出し側は、自身で数式インジェクション対策を行う責任を負う。
